# ISDB-Tフロントエンドの軽量化と受信検証

## 実装

RTL2832Uで128/63 MSpsを生成し、WASM内で64/63 MSpsへ2:1間引きする。
通常のRTL-SDR設定では周辺セグメントもUSBのIQに含まれるため、単純なサンプル破棄では
ワンセグ帯域への折り返しが発生する。純正ドライバの専用帯域制限設定は未確定。

ソフト側は汎用63タップFIRから、31タップの2:1専用ハーフバンドFIRへ変更した。

- 中央以外の交互の係数はゼロなので計算を省略する。
- 対称な係数の入力を先に足し、I/Qそれぞれ8組の積和＋中央1タップで処理する。
- 入力履歴は連続した配列に保持し、内側ループのリングバッファ折り返しをなくす。
- U8の変換、帯域制限、間引き、DC除去を1回のWASM呼び出しで処理する。
- 正規化は残す出力だけに適用する。分数位相の追跡・係数テーブル切り替えは不要。

TypeScript参照実装は通常のFIR積和を保持し、最適化したWASMとの一致を確認する。
回帰テストはチャンク分割・リセットに加え、±25/100/214/240 kHzの信号保持と、
そこへ折り返す帯域外信号の40 dB以上の抑圧を検証する。

## 前処理の実測

開発機で、100 ms分のU8 IQを同じ出力レートへ変換した結果。
JS側のU8展開、WASMとのコピー、出力配列の生成を含む。20回ウォームアップ後、
両経路を交互に100回測定した中央値。FFT/FECやブラウザ描画は含まない。

| 経路                                                 | 時間 / RF 100 ms |
| ---------------------------------------------------- | ---------------: |
| 従来1.2 MSps：U8展開＋DC除去＋32タップ分数リサンプラ |         約5.5 ms |
| ISDB-T：31タップ専用ハーフバンド融合処理             |         約1.8 ms |

この測定では前処理が約3倍高速、処理時間は約67%減少した。
変更前の汎用63タップ版は別測定で約13.8 msだった。
USB転送レートは128/63 MSpsのままなので、1.2 MSpsより約1.69倍多い。

再測定：

```bash
RUN_FRONTEND_BENCHMARK=1 npm test -- src/dsp/wasm/resample.bench.test.ts --disableConsoleIntercept
```

速度を固定閾値のテストにはしていない。ほかのテストと並列実行せず比較する。

## 実放送での検証

RTL2832U + FC0013、ゲイン19.7 dBで、19chと23chを128/63 MSps相当で各20秒録音した。
`rtl_sdr`は整数レート2031746 S/sを指定し、実レートは2031746.004407 S/sと報告した。

| 項目                         |                    19ch |                    23ch |
| ---------------------------- | ----------------------: | ----------------------: |
| TMCC                         | Mode 3 / GI 1/8、ロック | Mode 3 / GI 1/8、ロック |
| TSパケット                   |                    5410 |                    5396 |
| 映像PES / 音声PES            |                60 / 160 |                60 / 162 |
| 復調処理時間（20秒分）       |                 約9.7秒 |                 約9.9秒 |
| FFmpegで復号した映像フレーム |                     283 |                     272 |

両局でH.264 320×180、HE-AAC 48 kHzステレオの復号を確認した。
録音開始のSPS/PPS待ち・不完全なPESと、終了時の途切れによる警告はある。
先頭5秒と末尾を除いた10秒区間は、再エンコードせず抽出したうえで
FFmpegの`-xerror`付き映像・音声復号がエラーなしで完了した。
比較用に録音した従来1.2 MSpsの19chでも、映像・音声の復号と開始・終了付近の警告を確認した。

これは実機録音をアプリの`OneSegPipeline`で処理した結果であり、ブラウザのライブ描画の
自動検証ではない。IQとTSは`/tmp/opencode/`に置き、リポジトリには含めない。

再検証例（先にブラウザからデバイスを切断）：

```bash
rtl_sdr -f 509142857 -s 2031746 -g 19.7 -n 40634920 /tmp/opencode/isdbt19.u8
ISDBT_IQ_FILE=/tmp/opencode/isdbt19.u8 ISDBT_TS_FILE=/tmp/opencode/isdbt19.ts \
  npm test -- src/dsp/pipeline.test.ts -t 'ISDB-T hardware rate' --disableConsoleIntercept
ffmpeg -i /tmp/opencode/isdbt19.ts -map 0:v:0 -map 0:a:0 -f null -
ffmpeg -i /tmp/opencode/isdbt19.ts -ss 5 -t 10 -map 0:v:0 -map 0:a:0 \
  -c copy /tmp/opencode/isdbt19-middle.ts
ffmpeg -v error -xerror -i /tmp/opencode/isdbt19-middle.ts \
  -map 0:v:0 -map 0:a:0 -f null -
```

`-ss`は入力の後に指定し、不完全な先頭パケットを含む入力へのシークを避ける。
